# R0.1b — evidence-gated read-only research adapters

**Scope:** local, restricted internal-research interface over two separately stored SQLite databases. This is a library-only PR with no CLI, HTTP endpoint, public Quran/Tafsir UI integration, LLM calls or external network access.

- `quranenc_corpus` adapter: uses `corpus_sources` + `corpus_entries` from the existing immutable `mubin-private-corpus-v01.sqlite3` with five source IDs matching `research/corpora/import-sources-v01.json`; Quran (Tanzil candidate) plus four QuranEnc titles. Data row selectors use SQL parameters.
- `tafsircenter_sidecar` adapter: uses only `tafsir_tabary`, `tafsir_katheer`, `tafsir_baghawy`, `tafsir_saadi`, `tafsir_moyassar` and `QuranTafseer`. Coordinates are `sura, aya` on the first five, and `surahNo, ayahNo` on the sixth. Table and Arabic text column names are hard-coded; no user-defined SQL identifier is accepted.
- Both use SQLite `mode=ro&immutable=1`, `PRAGMA query_only=ON`, short-lived connections; no database schema modification, attachments, PRAGMA writes, SQL console or unlimited free-form search.
- **Mandatory external evidence:** every operation re-runs R0.1a `verify_evidence` against registry/HMAC key/out-of-vault anchor and currently held DB bytes before reading any source. No client-provided `verified` bool or source-status string can bypass that check. Source-kind, fixed hashes and rights flags from the corpus DB are checked against the committed pinned source manifest. Existing source files are assumed immutable while each read executes; concurrent modification or replacement of snapshot files is an operator security violation, not a supported live-write mode.
- **Metadata-only is the default.** `corpus_sources()`, `sidecar_sources()`, and `lookup(..., include_text=False)` do not read or return text/footnotes. A specific reference such as `2:1` yields `coordinate_present=true` and false flags, without copying private text to a JSON report.
- The explicit `include_text=True` code path is gated by a **separate local, externally issued HMAC-SHA256 permit**, bound to the current R0.1a evidence head, individual source IDs, purpose `restricted_internal_research`, bounded UTC expiry (24 hours maximum), a reviewed authorization ID, and `publication_allowed=false`, `p1_admitted=false`. The verification key and signed permit must live **outside** the vault and public Git checkout. The module contains **no permit issuer or auto-grant**, and never relies on a self-asserted Python boolean/dict as permission. The entity independently authorized to sign an internal research access grant must separately verify conditions through `core/internal_source_use.py` and associated operator/legal workflow **before issuing** a key-backed permit; an HMAC proves possession of the signing key, not the truth of legal attestation. If there is no approved external signing workflow, keep the grant absent and all private-text access disabled.
- **No text logging, automatic network use or public API:** private text returned only to the explicit in-process caller if an appropriate grant verifies. The caller must not forward this to LLMs, logs, UI or remote systems without separate authorization. Restrict the process, output handling, key custody and on-host users.

## Engineering qualification

CI runs entirely on synthetic SQLite fixtures and a synthetic test HMAC key. Real vault, source books, Tanzil/QuranEnc text, operator HMAC anchor/keys and campaign receipt do not enter GitHub Actions. Tests verify metadata-only no-text, five corpus IDs, six hardcoded sidecar tables, invalid references/table injection, evidence refusal, signing scope, corrupted/expired/wrong-head grants, and original-file immutability.

**Fail-closed legal and scholarly boundary:** `source_authenticated=false`, `rights_status=legal_review_pending`, `rights_verified=false`, `scholarly_verified=false`, `p1_admitted=false`, `publication_allowed=false`, `redistribution_approved=false`, `juristic_inference_allowed=false`, `public_fatwa_authorized=false`, including in explicitly approved local research text responses.

## Deliberately not in this PR

R0.1c's unified research result/CLI and R0.1d's independently reviewed legal/scholarly qualification ledger are separate gates. The entire Mubin platform remains `0.1.0-alpha`. Actual operator-only read tests of the 31,180-row corpus and 214 MB sidecar must occur separately and are **not asserted as CI evidence**.
