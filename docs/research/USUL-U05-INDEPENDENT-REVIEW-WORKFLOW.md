# U0.5 — سجل مهام التحكيم العلمي (غير المقدَّمة)

**إصدار مُبين العام:** `0.1.0-alpha`. U0.5 مرحلة أبحاث أصول الفقه الداخلية فقط، متراكبة على PR #69 (U0.4)، #68 (U0.3)، #67 (U0.2)، #66 (U0.1). هذه طبقة **سجل مهام** وليست نظام اعتماد شرعي أو سجلاً لهوية مراجعين حقيقيين.

## بيانات السجل

أربع مهام مراجعة، وكل مهمة تتطلب ستة محاور: مقابلة الطبعة، نسبة المؤلف/المحقق/المحاور، أساس الاستخدام، المنهج والخلاف، الشروط والموانع والأمثلة المضادة، ثم مراجعتان بشريتان مستقلتان. الحالات جميعها `pending`، والمراجعان لكل موضوع `unassigned`، وقائمة submissions **فارغة**، ولا توجد هوية أو توقيع في Git.

**ملاحظة علمية:** مسارات الموقع ليست صفحات المطبوعة. كل رقم صفحة وارد أعلاه قيمة عرض موقعية لم تُقابل independently مع طبعة محفوظة. لم تتم مراجعة حقوق نص الطبعة أو رواية نسخها. بصمات U0.2/U0.3/U0.4/U0.5 هي *بصمات بيانات سجل محلية*، لا بصمات ناشر أو حقوق.

## بوابات إثبات معلَّقة

1. `independent_edition_collation`: مقابلة أصل طبعة محدد وسلسلة حفظه ومواضع الحواشي.
2. `author_editor_attribution`: التمييز بين كلام المؤلف، المحاور، والحاشية وعنوان المحقق.
3. `legal_use_basis_review`: التحقق من الأساس النظامي لكل استخدام ونشر.
4. `methodology_and_disagreement_review`: توثيق مذهب الاستدلال والخلاف.
5. `conditions_exceptions_counterexamples`: نقض التعميم قبل اقتراح قاعدة.
6. `two_independent_scholarly_reviews`: مراجعان مؤهلان متحققان مستقلان، مع نتائج حقيقية غير مفترضة.

لا يجوز أن تتحول هذه الحقول إلى `completed` بمجرد تعديل JSON؛ تتطلب مراجع منفصلة وفحص الأدلة والهوية. وضع `accept/accept` في اختبار اصطناعي لا يثبت مراجعتين مستقلتين؛ لذلك يعيد `summarize_unverified_review_positions` دائمًا `independent_human_review_verified=false` و`eligible_for_engine=false`.

## تنفيذ هندسي مقيد

`core/usul/review_queue.py` يتحقق من الآباء U0.2 → U0.3 → U0.4 قبل U0.5؛ يرفض اختلاف الهويات والأسئلة والمواضع والترتيب، والحقول المخفية، والمراجعات أو التراخيص المزيفة. `core/usul/review_cli.py` يقرأ الملفات المحلية فقط باستخدام قارئ JSON المقيد (ملفات عادية ≤256KiB، منع NaN والمفاتيح المتكررة والروابط الرمزية)، ويعيد تقرير أعداد وبصمة وصفية فقط دون تسريب المقتطفات أو هويات مراجعين.

```bash
python -m unittest discover -s core/tests -v
python -m core.usul.review_cli research/usul/u05-risala-review-queue.json research/usul/u04-risala-text-observations.json research/usul/u03-risala-hypothesis-cards.json research/usul/u02-risala-source-candidates.json --json
```

نجاح CLI (exit 0) يعني **اتساق قائمة المهام غير المنفذة فقط**؛ exit 1 يعني بيانات غير مقبولة، exit 2 مدخلات ملف/JSON غير آمنة. عدد القواعد المعتمدة والمراجعات البشرية الحقيقية صفر، والاستنباط الآلي لا يبدأ. لا استخلاص جديد من H3.9.2 holdout.

## حدود القرارات اللاحقة

لا دمج على `main` دون ترتيب الاعتماديات، ولا منح اعتماد للمراجعين أو المصادر بالنموذج أو CI، ولا ترقية لحالة القاعدة، ولا تغيير لإصدار النظام العام. إن احتجنا مستقبلًا استقبال آراء بشرية فعلية فيجب وضع بياناتهم في خدمة خاصة بضوابط الهوية والموافقة والسرية، وليس في هذا المستودع العام.
