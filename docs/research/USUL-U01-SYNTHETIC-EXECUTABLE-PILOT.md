# U0.1 — محرك قواعد أصولية اصطناعي قابل للتنفيذ

**الحالة:** تنفيذ محلي تجريبي، غير مدمج في GitHub، وليس فقهًا آليًا أو فتوى أو توثيقًا لإسناد. **إصدار نظام مُبين الكلي ما يزال `0.1.0-alpha`.**

## الغرض والفرضيات

اختبار **شكل الاستدلال المقيّد** الذي قد نحتاج إليه لاحقًا في محرك أصول الفقه، دون افتراض اكتمال قواعد الاجتهاد أو صحتها الشرعية. لا نستعمل في هذه المرحلة نصوص القرآن أو الحديث أو كتب الفقه أو المصادر المحجوزة H3.9.2.

تختبر U0.1 الفرضيات التالية:

1. يمكن تمثيل شروط افتراضية مركبة في AST محدود بالعقد `fact`, `all`, `any`, `not` دون تنفيذ تعبيرات نصية برمجية.
2. لا يؤدي غياب مقدمة أو مجهوليتها إلى اعتبارها `false` أو استبدالها بحقيقة مفترضة.
3. الاستثناء المثبت يمنع تطبيق القاعدة؛ والاستثناء المجهول يجعل الاستنتاج معلقًا.
4. التضارب بين نتيجتين فاعلتين في **المنهجية المختارة نفسها** يظهر `conflict` بدل اختيار واحدة عشوائيًا.
5. المنهجية `method_a` منفصلة عن `method_b`: يمكن أن تتولد نتائج مختلفة من المدخلات نفسها، ولا يجوز سقوط منهجية إلى أخرى افتراضيًا.

جميع أسماء الفرضيات والنتائج `a`, `b`, ... و`track_north`, `track_south` **اصطناعية**. لا تمثل مذهبًا فقهيًا ولا تصحيحًا للحديث ولا حكمًا شرعيًا.

## لغة قواعد U0.1

`rulebook`: 

- `contract = mubin-usul-synthetic-rulebook-v1`
- `scope = synthetic_logic_not_fiqh_fatwa`
- `symbols`: مجموعة الحقائق الافتراضية المسموح بها.
- `methodologies`: معرفات مناهج منفصلة؛ كل منهج يحتوي قواعد مرتبة للعرض لكن ترتيبها **لا يقرر الترجيح**.
- `rule`: معرّف، السؤال، `when` شرط AST، `unless` استثناء AST اختياري، و`conclusion` مقصور على قيمتين اصطناعيتين.

`case` يتطلب `methodology_id`, `question_id`, `case_id` ومجموعة `facts` بقيم `established` أو `refuted` أو `unknown`؛ القيمة الغائبة تعامل `unknown`، وليس `refuted`.

### الدلالة الثلاثية (strong Kleene)

| التعبير | صحيح | خطأ | مجهول |
| --- | --- | --- | --- |
| `not(x)` | إذا كان x خطأ | إذا كان x صحيحًا | إذا كان x مجهولًا |
| `all(A,B)` | كل المتغيرات صحيحة | أي متغير خطأ | لا يوجد خطأ وبعض المتغيرات مجهول |
| `any(A,B)` | أي متغير صحيح | كل المتغيرات خطأ | لا يوجد صحيح وبعض المتغيرات مجهول |

- إذا ثبت `unless` => القاعدة `defeated` ولا تنتج نتيجتها، حتى لو بقي شرطها محل بحث.
- إذا لم يثبت شرط القاعدة (`false`) => `inapplicable`.
- إذا كان الشرط أو الاستثناء مؤثرًا وغير محسوم => `pending`، ثم `abstain` إذا لم توجد معارضة مثبتة أو `conflict` إذا ثبتت نتائج متعارضة بالفعل.
- إذا أنتجت القواعد الفاعلة نتيجتين مختلفتين => `conflict` مهما كان ترتيبها.
- إذا وُجدت قواعد `pending` مع نتيجة فاعلة واحدة => **امتناع احترازي** (`abstain`)، حتى لا تخفي قاعدة غير محسومة نتيجة معاكسة محتملة.
- لا توجد قاعدة فاعلة ولا معلقة => `abstain/no_applicable_rule`.
- المنهجية أو السؤال المجهول، مخطط خاطئ، تكرار المعرفات، AST معقد أو حقل زائد => `invalid`.

- ملف القواعد: `research/usul/rulebook-synthetic.json` — SHA-256 `a551b35678d6dc182f2e4cbab5e25cea8eb4b6392ee66eabc7a5cdc5611a02ea`.

- **15 حالة موجبة**: يجب أن تنجح وتختار `track_north` أو `track_south` بالضبط؛ يختبر مرجع مستقل جميع النتائج الـ15.
- **25 حالة مضادة**: تجهيل المقدمات، الاستثناءات، التعارض، غياب المنهج/السؤال، مخطط غير صالح، تكرار قواعد، رموز مجهولة، AST عميق، حقول حقن وغير ذلك.
- الحالات كتبت قبل تنفيذ المحرك، وحُفظ فشل الاستيراد الأول في ملف سجل منفصل. توفر بصمات SHA حماية من التعديل غير المقصود داخل هذه الحزمة؛ **ليست توقيعًا خارجيًا أو دليل تجميد مستقلًا عن منفذ التجربة**.
- حالات الحقائق اصطناعية فقط؛ نسبة 40/40 تقيس **اتساق التنفيذ مع هذا العقد المصطنع** ولا تقيس درجة علمية أو دقة فتوى أو أي قدرة خارج التوزيع.

## حدود التنفيذ

- الصيغ محدودة: 8 مستويات AST، و512 عقدة تعبير، و64 قاعدة إجمالًا، و8 مناهج، و32 رمزًا، ومدخلات CLI بحجم أقصى 256KiB لكل ملف، مع حماية من ملفات FIFO والروابط الرمزية وتكرار مفاتيح JSON وNaN والسلاسل Unicode غير الصالحة.
- يعتمد تحقق JSON Schema Draft 2020-12 على حزمة `jsonschema` الموجودة في متطلبات اختبارات مستودع مُبين؛ يمكن تثبيتها محليًا عند الحاجة.
- لا يوجد جلب من الشبكة أو تحميل مصدر أو كتابة سجل حقوق أو آلية وصول إلى ملفات محجوزة؛ ليس بوابة موافقة على نسخ كتاب. لا تُعد رموز `established` إثباتًا للحقيقة؛ هي معطى من المجرّب ضمن عالم مصطنع.
- تقارير `rule_traces` تظهر القواعد المحفزة والمعلقة والمغلوبة، ولا تثبت صحة قاعدة أصولية شرعًا أو نسبتها إلى مذهب.

## إعادة التشغيل

من جذر الحزمة وبعد تثبيت `jsonschema`:

```bash
python -m unittest discover -s core/tests -v
python -m compileall -q core/usul core/source_policy core/tests
python -m core.usul research/usul/rulebook-synthetic.json research/usul/test-cases-synthetic.json --json
```

ويمكن استخدام `evaluate(rulebook, case)` من `core.usul.engine` برمجيًا، مع فحص `scope=synthetic_logic_only` و`scholarly_authority_verified=false` دائمًا.

## الانتقال العلمي التالي — U0.2

1. تصميم **سجل قواعد أصولية موثقة علميًا**، كل قاعدة تشير إلى نص مؤلف، طبعة، موضع، انتماء منهجي، نطاق التطبيق، الاستثناءات وقواعد التعارض، مراجعة بشرية مستقلة.
2. إبقاء الحالات الاصطناعية المجمدة U0.1 دون تعديل أثناء تطوير U0.2، ووضع بيانات التطوير والتحقق العلمي في مجموعات منفصلة.
3. بناء مفردات صريحة للاختلاف الأصولي (الدلالة، العام والخاص، المطلق والمقيد، مفهوم المخالفة، القياس وشروطه) بعد تحديد المدارس والمصادر من أهل الاختصاص؛ **لم تُنفذ في U0.1**.
4. ربط أرقام المراجع وهويات الطبعات بـP1 بعد حسم حقوق نسخ المصدر والتحقق من bytes، وعدم دخول H3.9.2 holdouts تلقائيًا إلى التدريب.
5. قبل أي ادعاء فقهي: اختبارات تطبيقية محكّمة، وإظهار أسباب الامتناع وحدود الأدلة واختلاف المنهج، ومنع إطلاق الفتوى الآلية.

**لا يُفهم انتهاء هذا النموذج على أنه اكتمال محرك أصول الفقه أو محرك الفقه في مُبين.**
